# «Компас» — передача проекта команде разработки

> **Читать первым.** Это карта проекта для команды, которая будет **делать боевую версию по ТЗ**.
> Прототип — эталон поведения, **не основа для копирования кода**. Боевую пишем заново во
> внутреннем контуре (см. `docs/tech-task.md`).

Дата передачи: 20.11.2026.

---

## 1. Что это и в каком статусе

«Компас» встраивается перед формой **«ПЛАН РАЗВИТИЯ»**: в диалоге с ИИ оценивает разрыв между
текущей и целевой должностью, собирает черновик ИПР (цели, развивающие действия, сроки),
заземляя рекомендации на справочники (RAG), и возвращает готовый план обратно в форму.

- **Это прототип (MVP) / эталон.** Данные синтетические, вымышленные. Реальные ИПР и оценки
  во внешнюю LLM не уходят. **Боевой код из прототипа не берём** — только целевое поведение.
- Сквозной сценарий работает целиком и его стоит **сначала пройти руками**, чтобы увидеть цель.

**Главный документ — `docs/tech-task.md`** (постановка на боевую версию + таблица «что прототип
упрощал → что в бою делаем по-настоящему»). Начинать с него.

## 2. ⚠️ В репозитории ДВА стека — не перепутайте

Прототип развивался в два этапа. В коде лежат оба; **актуальный — второй**.

| | Старый стек (этап 1) | **Актуальный стек (этап 2) — эталон** |
|---|---|---|
| Фронт | `frontend/` (Angular 18) | **`frontend-v2/` (Angular 22, signals)** |
| API | `/api/*` (`ru.cft.kompas.*`), HS256-токен | **`/api/v1/*` (`ru.cft.kompas.v1.*`), Keycloak RS256 + SSE** |
| Авторизация | HMAC-токен входа | **Keycloak** (dev-мок `auth-mock/`) |
| LLM | gpt-4o-mini | **gpt-4.1** (fallback gpt-4o) |
| Запуск | `docker compose up` | **`run-*.ps1`** локально (кроме Postgres в docker) |
| Описан в | `README.md` (**частично устарел!**) | `docs/v1-integration-plan.md`, `docs/process-full.md` |

> **`README.md` описывает СТАРЫЙ стек** (frontend/, `/api/sessions`, 6 стадий, docker compose).
> Он полезен по доменной части и контракту экспорта, но запуск/эндпоинты там устаревшие.
> Для актуального поведения смотрите `frontend-v2` + `ru.cft.kompas.v1` + доки ниже.

Старый слой `/api/*` намеренно **не трогали** — он остался рабочим для совместимости.

## 4. Как запустить (актуальный стек, Windows)

Нужно: **JDK 21** (Temurin), **Node.js 20+**, **Docker** (только Postgres), PowerShell.

```powershell
# 0. .env — скопировать из шаблона и заполнить (см. §5)
copy kompas\.env.example kompas\.env

# 1. Postgres
docker compose up -d postgres          # :5433, БД/логин/пароль kompas

# 2. Mock-Keycloak (авторизация)
.\kompas\run-authmock-local.ps1        # :3000, realm compass

# 3. Backend «Компас»
.\kompas\run-backend-local.ps1         # :8090, /api/v1, живой LLM

# 4. Заглушка «ПЛАН РАЗВИТИЯ» (точка входа)
.\kompas\run-legacy-local.ps1          # :8081

# 5. Фронт
cd kompas\frontend-v2 && npm install && npm start   # :4200
```

**Сценарий:** открыть **http://localhost:8081** → войти (Keycloak, **demo / demo**) → выбрать
сотрудника → «**Сформировать с помощью Компаса**» → диалог на :4200 → черновик → экспорт обратно.

Порты 8090/5433 выбраны, чтобы не конфликтовать (8080/5432 часто заняты).
**Без ключа LLM:** в `.env` поставить `SPRING_PROFILES_ACTIVE=local` — включается офлайн-заглушка,
сценарий проходится целиком на детерминированных ответах.

> **Важно:** backend и legacy-stub поднимать **только через `run-*.ps1`** — они берут общий
> `JWT_SECRET` и ключ LLM из `kompas/.env`. Голый `gradlew bootRun` подпишет токен дефолтным
> секретом, и «Компас» отвергнет вход.

## 5. Секреты и крупные файлы (их НЕТ в архиве)

- **`kompas/.env` в архив не входит** (секреты). Заполнить из `kompas/.env.example`:
  - `LLM_API_KEY` — ключ OpenRouter (или свой OpenAI-совместимый шлюз). Пусто + профиль `local` — офлайн.
  - `JWT_SECRET` — общий HMAC-секрет (≥32 симв.), одинаковый у backend и legacy-stub.
- **Vosk-модель STT** (`frontend-v2/public/models/vosk-model-small-ru-0.22.tar.gz`, ~45 МБ) —
  вложена в архив отдельно (нужна для голосового ввода). Если потеряется — качается с
  alphacephei.com (`vosk-model-small-ru-0.22`). Голосовой ввод **опционален**; в бою STT —
  во внутреннем контуре (Whisper on-prem / SpeechKit).
- `node_modules`, `build/`, `.angular/`, `.gradle/` в архив не вошли — ставятся/собираются заново.

## 7. Что в бою делаем иначе (прототип → боевая) и открытые вопросы

Из `tech-task.md` §2 и `handoff-context.md`:

- **LLM:** внешний OpenRouter (gpt-4.1) → **внутренний шлюз `ai.redelephant`**, без внешних вызовов.
- **Авторизация:** `auth-mock` → **реальный SSO/Keycloak ЦФТ**.
- **Эмбеддинги/RAG:** локальное хеширование + косинус в памяти → настоящая модель + **pgvector**.
- **Справочники:** сид из xlsx → **системы-источники компании**, единый источник.
- **Перенос в «План развития»:** сейчас отрисовка формы → **запись** приоритетов/действий в БД/через API.
- **STT:** vosk-small (качество низкое) → on-prem Whisper / SpeechKit.

**Главный открытый вопрос:** источник контекста сотрудника — entry-токен vs прямой доступ к
`Orgstructure VW_COMPASS_EMPLOYEES`. См. `process-full.md` (7 вопросов для боя) и
`handoff-context.md` §«Открытые вопросы к "Плану развития"».

**Известные слабые места качества плана в прототипе** (можно улучшить в бою):
дедуп направлений только по коду компетенции (не по смыслу); иногда «мусорная» категория от
авто-снапа; пересборка `order_no` после слияния. Детерминизм генерации неполный.

## 8. Среда (грабли Windows)

- Нужен **JDK 21** (Temurin `C:\Program Files\Eclipse Adoptium\jdk-21...`); gradle-wrapper вложен.
- Порты 8080/5432 часто заняты → сервис на **8090/5433**.
- У legacy-stub включён **content-hash на статику**: после правки CSS изменения видны **только
  после рестарта** приложения (не по F5).
- `.env` — единственное место секретов, в архиве его нет.
