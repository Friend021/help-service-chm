# Данные о сотруднике для формирования ИПР

Что нужно знать о сотруднике, чтобы (а) задать ему релевантные вопросы и
(б) собрать индивидуальный план развития (ИПР).

Данные делятся на два потока:
- **Из систем** — тянем до диалога (SSO, кадровая БД / сервис «План развития», справочники компании).
- **Из диалога** — добираем в разговоре с сотрудником.

Логика: из систем получаем «кто он и каким должен быть» (должность + требования + текущий
уровень), в диалоге добираем «чего хочет и что может» (цель, приоритеты, ограничения),
а **разрыв между требуемым и текущим уровнем** превращаем в пункты ИПР, наполняя их
активностями из справочника.

---

## 1. Идентификация и орг-контекст
*Источник: SSO-токен + кадровая БД*

| Поле | Назначение | Обяз. |
|---|---|---|
| ФИО | отображение, авторство | да |
| Внутренний ID (табельный) | ключ сотрудника | да |
| email | связь, уведомления | нет |
| Подразделение, команда | контекст | да |
| Руководитель (ФИО + ID) | согласование ИПР | да |
| Дата найма → стаж в компании / в должности | ветвление сценария, тон вопросов | нет |
| Локация / часовой пояс | планирование сроков | нет |

## 2. Должностной контекст — «откуда и куда»
*Источник: кадровая БД. Ядро — задаёт направление развития*

| Поле | Назначение | Обяз. |
|---|---|---|
| Текущая должность (код + название) | опорная точка | да |
| Ожидаемая / целевая должность (код + название) | цель развития, gap | нет |
| Грейд / уровень текущий и целевой | масштаб разрыва | нет |
| Тип сценария: новый / в должности / переход | выбор ветки и набора вопросов | да |
| Карьерный трек (экспертный / управленческий) | акценты плана | нет |

## 3. Требования к должности — «про что спрашивать»
*Источник: справочники компании (слой RAG). Главный источник вопросов*

| Поле | Назначение | Обяз. |
|---|---|---|
| Должностная инструкция (обязанности) | основа вопросов | да* |
| Профиль должности (требуемые компетенции + целевые уровни) | что оцениваем | да* |
| Модель компетенций (компетенция → индикаторы → уровни) | шкала и формулировки | да |
| Требования целевой должности | gap до цели | нет |

\* Достаточно **одного** из двух (ДИ или Профиль должности). Если нет ни того, ни
другого — срабатывает fallback (опрос по ожидаемой роли / ручной ввод роли).

> По каждой требуемой компетенции задаём вопрос на самооценку.

## 4. Текущий уровень — «чтобы считать разрыв (gap)»
*Источник: оценки (если есть) + сам диалог*

| Поле | Назначение | Обяз. |
|---|---|---|
| Результаты последней оценки (руководитель / 360 / ассессмент) | объективный вход | нет |
| Самооценка по компетенциям | **собирается в диалоге** | да (диалог) |
| Hard/soft skills, сертификаты, пройденное обучение | что уже закрыто | нет |
| KPI / результаты по целям | где «западает» | нет |

> **Разрыв = целевой уровень − текущий (оценка или самооценка).** Основа пунктов ИПР и приоритетов.

## 5. История развития — «чтобы не дублировать»
*Источник: сервис «План развития»*

| Поле | Назначение | Обяз. |
|---|---|---|
| Прошлые ИПР и их статус (выполнено / нет) | не повторять закрытое | нет |
| Пройденные курсы и активности | исключить из рекомендаций | нет |
| Обратная связь (руководитель / наставник) | акценты | нет |

## 6. Цель и предпочтения сотрудника
*Источник: сам диалог*

| Поле | Назначение | Обяз. |
|---|---|---|
| Ключевая цель создания ИПР | зачем строим план | да (диалог) |
| Карьерные амбиции / желаемое направление | персонализация | нет |
| Приоритеты — что важнее развить | порядок направлений | да (диалог) |
| Ограничения: время (ч/нед), формат, бюджет | реалистичность действий | нет |
| Горизонт планирования (6 / 12 мес) | сроки | да (диалог) |

## 7. Каталог развивающих активностей — «чем наполнять действия»
*Источник: справочник активностей*

| Поле | Назначение | Обяз. |
|---|---|---|
| Инструменты развития (курсы, менторинг, проекты, литература, ротация) | действия ИПР | да |
| Привязка активности к компетенциям | подбор под разрыв | да |
| Длительность / доступность / стоимость | фильтр по ограничениям | нет |

---

## Минимум для старта

Без этих данных диалог запустить нельзя:

| Нужно обязательно | Почему |
|---|---|
| Текущая должность | опорная точка |
| ДИ **или** Профиль должности | иначе нечего спрашивать → fallback |
| Модель компетенций | из неё растут вопросы |
| Каталог активностей | иначе ИПР = цели без действий |

Целевая должность, прошлые оценки и стаж **улучшают персонализацию**, но не блокируют старт.
Цель, приоритеты и предпочтения **добываются в диалоге** — их не обязательно иметь на входе.

## JSON-контракт `EmployeeContext`

Входная структура для диалогового движка. Поля помечены: `required` — обязательно на
входе; `dialog` — заполняется в ходе диалога; остальное опционально.

```jsonc
{
  "employee": {                         // 1. Идентификация и орг-контекст
    "id": "string",                     // required
    "fullName": "string",               // required
    "email": "string | null",
    "unit": "string",                   // required — подразделение
    "team": "string | null",
    "manager": {                        // required — для согласования
      "id": "string",
      "fullName": "string"
    },
    "hiredAt": "date | null",
    "tenureMonths": "number | null",    // стаж в компании
    "positionTenureMonths": "number | null",
    "timezone": "string | null"
  },

  "position": {                         // 2. Должностной контекст
    "current": {                        // required
      "code": "string",
      "title": "string",
      "grade": "string | null"
    },
    "target": {                         // опц. — цель развития
      "code": "string",
      "title": "string",
      "grade": "string | null"
    },
    "scenario": "NEW | IN_ROLE | TRANSITION",   // required
    "careerTrack": "EXPERT | MANAGER | null"
  },

  "requirements": {                     // 3. Требования к должности (RAG)
    "jobDescription": "string | null",          // ДИ; хотя бы одно из двух
    "roleProfile": {                             // Профиль должности
      "competencies": [
        { "code": "string", "name": "string", "targetLevel": "number" }
      ]
    } ,
    "competencyModel": [                 // required — справочник
      {
        "code": "string",
        "name": "string",
        "levels": [
          { "level": "number", "indicator": "string" }
        ]
      }
    ],
    "grounded": "boolean"                // false → черновик «без заземления»
  },

  "assessment": {                       // 4. Текущий уровень
    "lastReview": [                     // опц. — объективная оценка
      { "competencyCode": "string", "level": "number", "source": "MANAGER | 360 | ASSESSMENT" }
    ],
    "selfAssessment": [                 // dialog — самооценка
      { "competencyCode": "string", "level": "number" }
    ],
    "skills": ["string"],
    "certificates": ["string"]
  },

  "history": {                          // 5. История развития
    "pastPlans": [
      { "id": "string", "period": "string", "status": "DONE | NOT_DONE | IN_PROGRESS" }
    ],
    "completedActivities": ["string"],
    "feedback": ["string"]
  },

  "intent": {                           // 6. Цель и предпочтения (dialog)
    "keyGoal": "string",                // dialog — ключевая цель ИПР
    "aspirations": "string | null",
    "priorities": ["string"],           // dialog — порядок направлений
    "constraints": {
      "hoursPerWeek": "number | null",
      "format": ["IN_PERSON | ONLINE | SELF"],
      "budget": "number | null"
    },
    "horizonMonths": "number"           // dialog — 6 / 12
  },

  "activitiesCatalog": [                // 7. Каталог активностей (required)
    {
      "id": "string",
      "title": "string",
      "type": "COURSE | MENTORING | PROJECT | BOOK | ROTATION",
      "competencyCodes": ["string"],   // привязка к компетенциям
      "durationHours": "number | null",
      "available": "boolean",
      "cost": "number | null"
    }
  ]
}
```

### Как это используется движком
1. **Генерация вопросов** — из `requirements` (ДИ / профиль / модель компетенций) берутся
   требуемые компетенции → по каждой вопрос на самооценку.
2. **Самооценка** → пишется в `assessment.selfAssessment`.
3. **Расчёт разрыва** — `targetLevel − (lastReview ?? selfAssessment)` по каждой компетенции.
4. **Приоритизация** — разрыв × `intent.priorities`.
5. **Наполнение действий** — для компетенций с разрывом подбираются активности из
   `activitiesCatalog` по `competencyCodes`, с фильтром по `intent.constraints`.
6. **Сборка ИПР (JSON)** — направления (компетенции) + цель + действия (активности) + сроки.
