# Контракт входа: «ПЛАН РАЗВИТИЯ» → «Компас»

Обе стороны интеграции в макете наши, поэтому контракт зафиксирован здесь.

## 1. Точка входа

Заглушка отдаёт страницу-форму на `http://localhost:8081/`. Кнопка
**«Сформировать с помощью Компаса»** ведёт на:

```
GET http://localhost:8081/kompas?employee=<externalId>
```

Заглушка формирует подписанный JWT и отвечает редиректом:

```
302 Location: http://localhost:4200/entry?token=<JWT>
```

Базовый URL «Компаса» задаётся переменной `KOMPAS_FRONTEND_URL`
(в контейнере — `LEGACY_KOMPAS_FRONTEND_URL`).

## 2. Токен входа

| Параметр | Значение |
|---|---|
| Алгоритм | HMAC-SHA256 (`HS256`) |
| Секрет | `JWT_SECRET` из `.env`, общий для заглушки и «Компаса», минимум 32 байта |
| TTL | 10 минут (`legacy.jwt-ttl`) |
| Передача | query-параметр `token` |

### Claims

| Claim | Обязателен | Описание |
|---|---|---|
| `employeeExternalId` | да | Идентификатор сотрудника во внешней системе |
| `fullName` | да | ФИО сотрудника |
| `currentPosition` | нет | Название текущей должности |
| `targetRole` | нет | Название целевой роли |
| `careerTrack` | нет | Карьерный трек |
| `managerFullName` | нет | ФИО руководителя |
| `managerExternalId` | нет | Идентификатор руководителя |
| `iss` | да | `legacy-plan-razvitiya` |
| `sub` | да | Дублирует `employeeExternalId` |
| `iat`, `exp` | да | Выдан / истекает |

Пример payload:

```json
{
  "iss": "legacy-plan-razvitiya",
  "sub": "emp-001",
  "employeeExternalId": "emp-001",
  "fullName": "Соколова Анна Дмитриевна",
  "currentPosition": "Разработчик Java",
  "targetRole": "Ведущий разработчик Java",
  "careerTrack": "Разработка ПО",
  "managerFullName": "Верещагин Олег Борисович",
  "managerExternalId": "mgr-001",
  "iat": 1790000000,
  "exp": 1790000600
}
```

## 3. Приём входа в «Компасе»

1. SPA открывает маршрут `/entry?token=...`, забирает токен из query.
2. SPA вызывает `POST /api/sessions` с телом `{"token": "<JWT>"}`.
3. Бэкенд проверяет подпись и срок (`JwtEntryTokenVerifier`).
4. По `employeeExternalId` находится или заводится `Employee`;
   `currentPosition` и `targetRole` сопоставляются со справочником должностей по названию
   (если должности нет — заводится запись без компетенций, контекст не теряется).
5. Создаётся `DialogSession` в стадии `CONTEXT`, ассистент делает первый ход.
6. В ответ приходит `accessToken` (TTL 12 часов) — им подписываются все последующие вызовы API
   заголовком `Authorization: Bearer <accessToken>`.

Разделение на два токена сделано намеренно: короткий TTL токена входа нужен
для безопасности перехода, но не должен обрывать диалог через 10 минут.

## 4. Поведение при ошибке

| Ситуация | HTTP | Что видит сотрудник |
|---|---|---|
| Нет параметра `token` | — | «В ссылке нет токена входа» |
| Подпись не сходится | 401 | «Токен входа недействителен или истёк» |
| Токен просрочен | 401 | То же + подсказка вернуться в «ПЛАН РАЗВИТИЯ» |
| Истёк `accessToken` | 401 | Редирект на `/entry` |

## 5. Пример кнопки в заглушке

```html
<a class="btn btn--kompas" th:href="@{/kompas(employee=${employee.externalId})}">
    Сформировать с помощью Компаса
</a>
```

## 6. Что меняется при переходе в бой — [POST-MVP]

- HMAC заменяется на асимметричную подпись или реальный SSO: нужна другая реализация
  `EntryTokenVerifier`, контракт claims сохраняется.
- Токен переносится из query в заголовок или в короткоживущий code-exchange.
