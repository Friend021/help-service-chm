## Сверх ТЗ

- **Возврат плана в форму** (ТЗ относило к `[POST-MVP]`): кнопка «Перенести
  в ПЛАН РАЗВИТИЯ», подписанная ссылка, форма открывается заполненной.
- **Классификация по справочникам формы**: рубрика цели и инструмент развития
  выбираются из справочников старого сервиса и сверяются с ними.
- **Развивающие действия** под каждой целью — инструмент, конкретное действие,
  срок, статус.

## Что осталось

### 1. Не прогнан сквозной путь ручной правки после перестройки модели

Формат `PUT /api/idp/{id}` сменился: вместо `activityCodes` и `milestones` там
теперь `actions`. Кнопка «Править» в панели после этого в браузере не тестировалась —
смена инструмента в селекте, срок, удаление действия, сохранение. Юнит-тесты
покрывают применение черновика, но не путь через UI.

Единственное место, где может лежать настоящая поломка. Проверять первым.

### 2. Ветка не влита в master

```bash
git checkout master && git merge kompas-idp-mvp
```

### 3. Заголовки блоков действий дублируются

Когда компетенции расползаются по нескольким приоритетам, блоки получают почти
одинаковые названия («Проектирование компонентов и API» и рядом
«Проектирование компонентов и API; Коммуникация с заказчиком»).
Варианты: пронумеровать блоки или подтянуть промпт, чтобы компетенция
не повторялась в разных приоритетах.

### 4. Иконки грузятся из интернета

Material Icons тянутся с `fonts.googleapis.com`. В закрытом контуре ЦФТ
их не будет — кнопки покажут текст вместо значков. Нужен локальный шрифт.
Блокер для показа внутри компании, не блокер для демо с ноутбука.

### 5. Мелочи

- Сборка черновика занимает 15–80 секунд: два вызова модели из-за авто-догона.
  Лечится стримингом ответа.
- `.gitattributes` с `eol=lf`, если репозиторий поедет на Linux-сборку.
- Заглушка отдаёт 404 на favicon — косметика внутри мока.
- Эндпоинты `/api/reference/*` работают, но фронтом не используются: задел
  под ручной подбор активностей.

## Известные ограничения макета

- **План переносится в отображение формы, а не в базу старого сервиса** —
  своего хранилища у заглушки нет. Состав полей уже совпадает, в бою этот шаг
  заменяется записью в БД «ПЛАНА РАЗВИТИЯ».
- **Справочники продублированы** в «Компасе» и в заглушке и должны совпадать:
  рубрики целей и инструменты развития. В бою «Компас» получал бы их из старого
  сервиса.
- **Эмбеддинги лексические**, без понимания синонимов. Для 48 демо-фрагментов
  достаточно; на реальном корпусе нужна настоящая модель за `EmbeddingClient`.
- **Данные синтетические** (раздел 13 ТЗ). Реальные ИПР во внешнюю LLM
  не отправляются.
