# LLM и RAG в макете

## 1. Что выбрано и почему

| Слой | Реализация по умолчанию | Интерфейс |
|---|---|---|
| Чат-модель | OpenRouter, `openai/gpt-4o-mini` | `LlmClient` |
| Офлайн-режим | `MockLlmClient` | `LlmClient` |
| Эмбеддинги | локальное хеширование | `EmbeddingClient` |
| Векторный поиск | in-DB (вектор строкой в `reference_chunk.embedding`) | `VectorStore` |

`openai/gpt-4o-mini` выбран как дешёвая и быстрая модель, достаточная для диалога
с жёстким форматом ответа. Контракт OpenRouter — OpenAI-совместимый, поэтому любой
другой провайдер (OpenAI, локальный OpenAI-совместимый сервер) подключается
сменой `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`, без правки кода.

**Эмбеддинги берём локальные, а не у провайдера.** У OpenRouter нет стабильного
эндпоинта `/embeddings`, и завязка на него сделала бы макет неработоспособным при
первой же смене провайдера. `LocalHashingEmbeddingClient` детерминирован, не требует
сети и достаточен для лексического поиска по демо-справочникам из нескольких десятков
фрагментов. Если у провайдера эндпоинт есть — включается `OpenAiEmbeddingClient`:

```
KOMPAS_EMBEDDINGS_PROVIDER=openai
KOMPAS_EMBEDDINGS_MODEL=text-embedding-3-small
```

`pgvector` намеренно не используется: демо-корпус мал, косинусная близость считается
в памяти. Переход на pgvector — это другая реализация `VectorStore`, схема БД не меняется.

## 2. Как получить ключ

1. Зарегистрироваться на https://openrouter.ai
2. Keys → Create key.
3. Пополнить баланс: бесплатные модели OpenRouter отдают 429 на задачах
   с большим выходом — для этого сценария они не годятся.
4. Положить ключ в `.env`:

```
LLM_PROVIDER=openrouter
LLM_API_KEY=sk-or-v1-...
LLM_MODEL=openai/gpt-4o-mini
```

## 2.1. Лимиты провайдера и запасная модель

Часть моделей идёт на OpenRouter через **общий пул upstream-провайдера** и периодически
отвечает `429 ... temporarily rate-limited upstream`. Это не ошибка ключа и не нехватка
денег — пул делится между всеми пользователями OpenRouter. На `qwen/qwen3.8-flash`
(пул Alibaba) это воспроизводится регулярно.

Что сделано, чтобы диалог это переживал:

1. **Повторы.** `OpenRouterClient` повторяет запрос до 3 раз при `429` и `5xx`
   с нарастающей паузой (1,5 с → 3 с). Остальные коды не повторяются.
2. **Запасная модель.** Если задан `LLM_FALLBACK_MODEL`, в запрос уходит
   `models: [основная, запасная]` — OpenRouter сам уходит на запасную,
   когда основную лимитируют.

```
LLM_MODEL=qwen/qwen3.8-flash
LLM_FALLBACK_MODEL=openai/gpt-4o-mini
```

Если модель важнее устойчивости — оставьте `LLM_FALLBACK_MODEL` пустым; тогда при
исчерпании повторов сотрудник увидит понятное сообщение, а не общую ошибку.

## 3. Офлайн-запуск

```
SPRING_PROFILES_ACTIVE=local
```

Профиль `local` принудительно включает `MockLlmClient` и локальные эмбеддинги —
внешних вызовов нет вообще. Мок читает стадию и коды `[COMP:...]` / `[ACT:...]`
из RAG-контекста и отдаёт ответ в том же JSON-формате, что и боевая модель,
поэтому весь сценарий проходится без ключа и без сети.

## 4. Как устроено заземление (RAG)

На каждом ходу `Retriever` собирает блок «КОНТЕКСТ СПРАВОЧНИКОВ»:

1. **Должностная инструкция целевой роли** — целиком.
2. **Компетенции целевой роли** — все, а не top-K: их единицы, и ассистент обязан
   опираться именно на них.
3. **Каталог активностей** — сначала связанные с компетенциями роли, затем добор
   векторным поиском по тексту сообщения.

Коды подаются в формате `[COMP:LJD-01]` и `[ACT:ACT-001]`. Системный промпт запрещает
использовать любые другие коды, а `DraftParser.sanitize()` дополнительно вырезает из
черновика всё, чего не было в контексте, и пишет предупреждение в лог. Так требование
ТЗ «рекомендации из реального контекста, а не выдуманные» выполняется на двух уровнях:
инструкцией и кодом.

## 5. Формат ответа модели

Модель отвечает одним JSON-объектом:

```json
{
  "message": "текст для сотрудника",
  "nextStage": "DRAFT",
  "draft": {
    "targetRole": "Ведущий разработчик Java",
    "priorities": [
      {
        "order": 1,
        "developmentGoal": "цель по SMART",
        "competencyCodes": ["LJD-01"],
        "activityCodes": ["ACT-001"],
        "milestones": [{"title": "...", "dueDate": "2026-12-31"}]
      }
    ]
  }
}
```

Если формат нарушен — один корректирующий повтор запроса; если и он не помог,
текст показывается как есть, а стадия не двигается (ход не теряется).

Шаблоны промптов лежат в `backend/src/main/resources/prompts/` и версионируются
отдельно от кода.

## 6. Переход на ai.redelephant — [POST-MVP]

1. Добавить `RedElephantClient implements LlmClient` в пакет `llm`.
2. Добавить ветку в `LlmConfig.llmClient()`:

```java
case "redelephant" -> new RedElephantClient(properties.getLlm(), objectMapper);
```

3. Переключить конфигом:

```
KOMPAS_LLM_PROVIDER=redelephant
```

Ничего больше менять не нужно: диалоговый движок, RAG и парсер работают с интерфейсом.

## 7. Приватность

Данные макета — синтетические (раздел 13 ТЗ). Реальные ИПР и результаты оценки во
внешнюю LLM не отправляются: внешний провайдер допустим только на этапе макета.
В бою обработка идёт во внутреннем контуре через `ai.redelephant`.
Содержимое ИПР и PII не логируются выше уровня DEBUG.
